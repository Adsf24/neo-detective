# NEO DETECTIVE — MVP за 3 дня (хакатон Meta)

Вводные: 3 дня, код пишет Claude в основном автономно, персонажи на Llama (кредиты Meta, ~$150), демо и игра на английском, новый репозиторий на GitHub. 16-недельный план (neo-detective-roadmap.md) — это продукт; здесь — играбельный срез для жюри.

## Что показываем жюри

Компания из 3–4 человек открывает ссылку или QR на своих телефонах и за 20–30 минут раскрывает дело «The Missing Original» (английская версия «Пропавшего архива»): роется в почте и компьютере галереи, разглядывает фотографии, **звонит ИИ-свидетелям голосом**, предъявляет им улики, ловит Марину на лжи, спорит над Доской и выносит обвинение, которое игра оценивает по доказательствам. В конце — реконструкция и история именно этой команды.

Одна фраза для питча: *the evidence isn't handed to you — you dig it out, and the witnesses talk back.*

## Ключевое архитектурное решение

**Персонаж знает только то, что готов сказать сейчас.** Вместо «LLM знает всю правду и обещает молчать» плюс отдельный верификатор движок перед каждой репликой вычисляет, какие факты персонажу разрешено раскрыть: по предъявленным уликам, по тому, кто спрашивает, по уже сделанным признаниям и по классу вопроса. Модель получает биографию, характер, легенду (cover story) и *только разблокированные* факты. Утечь то, чего модель не видит, нельзя.

Это делает контракт детерминированным (таблица признаний Марины — это код, не промпт), снимает зависимость от того, насколько хорошо модель держит инструкции, и избавляет от отдельного прохода верификатора, который стоил бы задержки. Для хакатона это ещё и хорошая история для жюри: *the truth lives in the engine, not in the prompt.*

Цикл реплики:
1. Вопрос игрока (текст или распознанная речь) + предъявленные улики.
2. Быстрый вызов Llama классифицирует вопрос: тема, прямой ли вопрос о скрываемом, грубость.
3. Движок применяет правила контракта → набор разблокированных фактов, изменения доверия, триггеры событий.
4. Вызов Llama в роли персонажа со структурированным ответом `{reply, mentioned_fact_ids}`.
5. Лёгкая проверка: `mentioned_fact_ids` ⊆ разблокированным; иначе — повтор или безопасная реплика.
6. Ответ → TTS → всем участникам звонка + расшифровка.

## Стек (по умолчанию, без обсуждения)

| Слой | Выбор | Почему |
|---|---|---|
| Язык | TypeScript везде | Одна модель типов для дела, сервера и клиента |
| Клиент | Vite + React, мобильная вёрстка, PWA-манифест | Быстро, без SSR-сложностей |
| Сервер | Node + Fastify + Socket.IO, комнаты в памяти | Реалтайм из коробки; персистентность не нужна |
| Деплой | Один контейнер на Fly.io или Railway | WebSocket работает, один инстанс |
| LLM | Llama API через интерфейс провайдера; быстрая модель для классификации, сильная — для персонажей | Требование хакатона; интерфейс позволяет сравнить и откатиться |
| STT | Web Speech API в браузере (Chrome), запасной вариант — ввод текстом | Бесплатно, быстро, ноль бэкенда |
| TTS | Сначала браузерный speechSynthesis; если остаётся время — облачный TTS с разными голосами | Голос с первого дня; качество — улучшение |
| Тесты | Vitest для движка, Playwright с 3 браузерными клиентами для сквозных сценариев | Автономный Claude должен уметь проверять себя сам |
| Дело | JSON-пакет со схемой (zod) | Дело — данные; второе дело без кода |

## Что режем из GDD

Нет: аккаунтов, оплаты, каталога, персистентности (перезапуск сервера — комнаты пропадают), реальных email, профессий, сайтов, камер с задержкой, конфронтации, семейного режима. Актов два, не три. Одно дело. Голос — только Chrome; остальные браузеры — текст.

Остаётся всё, что делает игру социальной: личные стартовые материалы, Доска, личные контакты (Олег говорит только с игроком C), совместный звонок на одном телефоне с расшифровкой у всех, Совет, переход акта с рабочей версией, тайный предварительный вердикт, реактивное событие (Марина удаляет письмо), поддерживающие подсказки, обвинение по графу доказательств, реконструкция и история команды.

## Как Claude работает автономно

- Каждая задача — issue в Linear с критерием «готово, когда», который проверяется тестом.
- Два потока в день — две сессии в отдельных git worktree, у каждой свои файлы; слияние в main вечером, после зелёного CI.
- Движок покрывается юнит-тестами до клиента; сквозные сценарии — Playwright с несколькими клиентами. Claude не считает задачу готовой без зелёного теста.
- Контент дела меняется только в `cases/` — код не знает про Марину.
- Vic подключается в трёх точках: конец дня 1 (поиграть на телефоне), конец дня 2 (прогон с голосом), утро дня 3 (плейтест). Плюс всё, что требует ключей и аккаунтов.

## Риски и запасные варианты

| Риск | Признак | Запасной вариант |
|---|---|---|
| Llama плохо держит роль или JSON | 0.4 и 2.2 — невалидный JSON или выход из роли | Строгий режим JSON, короче промпты, больше логики в движке; крайний случай — переключение провайдера через интерфейс |
| Задержка голоса | 2.4 — больше 3 с | Анимация «думает», более быстрая модель для персонажей, совместный звонок текстом + TTS |
| Web Speech API плохо распознаёт | шум зала на демо | Push-to-talk с явным подтверждением текста перед отправкой |
| Деплой WebSocket | 0.3 не взлетает | Другой хостинг; в крайнем случае туннель с ноутбука на демо |
| Изображения с неверными деталями | 1.8 | Детали — наложенные слои, не часть генерации |
| Сеть на площадке | демо | Раздача с телефона, демо-комната, видео как запасной вариант |
| Не успеваем | вечер дня 2 нет звонков | Режем: ответ письмом, входящие, голос — совместный звонок текстом остаётся |

## Порядок урезания, если не успеваем

1. Облачный TTS → браузерный.
2. Ответ персонажу письмом.
3. Входящие звонки.
4. Хронология с подсветкой на Доске → простой список.
5. История команды → только реконструкция.

Неприкосновенно: звонки с предъявлением улик, Марина по контракту, Доска, Совет, переход акта, вердикт, обвинение с оценкой.
